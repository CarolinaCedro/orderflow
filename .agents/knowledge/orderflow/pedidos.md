# Order Domain — OrderFlow Deep Knowledge

Complete reference for the Order domain: entity structure, lifecycle, listeners, and status flow.

---

## Order Entity

Defined in `order-model`: `org.cedro.ordermodel.model.Order`

```java
@Data
@AllArgsConstructor
@NoArgsConstructor
@Document(collection = Order.ORDERS_COLLECTION)
public class Order {

    public static final String ORDERS_COLLECTION = "orders";

    @Id
    private String id;                       // MongoDB ObjectId string

    @NotBlank(message = "customerId is required")
    private String customerId;               // External customer reference

    @NotBlank(message = "customerName is required")
    private String customerName;

    @NotEmpty(message = "Order must have at least one item")
    @Valid
    private List<OrderItem> items;           // Embedded documents — validated recursively

    @NotNull(message = "totalAmount is required")
    @Positive(message = "totalAmount must be positive")
    private BigDecimal totalAmount;          // Must be > 0

    private OrderStatus status;              // Set by system (not client)
    private ApprovalStatus approvalStatus;   // Set by system

    private String approvedBy;              // "payment-service" after payment
    private LocalDateTime approvalDate;

    private String erpOrderId;              // External ERP reference (future use)

    private Metadata metadata;              // Auto-populated by OrderMetadataListener
}
```

Fields NOT required in the request body (set by the system):
- `id` — generated by MongoDB
- `status` — set to initial value by service or by Kafka listener
- `approvalStatus` — set by `OrderPaymentListener`
- `approvedBy` — set by `OrderPaymentListener` to `"payment-service"`
- `approvalDate` — set by `OrderPaymentListener`
- `metadata` — populated by `OrderMetadataListener`

## OrderItem Entity

Defined in `order-model`: `org.cedro.ordermodel.model.OrderItem`

```java
@Getter
@Setter
@ToString
public class OrderItem {

    @NotBlank(message = "productId is required")
    private String productId;

    @NotBlank(message = "productName is required")
    private String productName;

    @NotNull(message = "quantity is required")
    @Positive(message = "quantity must be positive")
    private Integer quantity;

    @NotNull(message = "unitPrice is required")
    @Positive(message = "unitPrice must be positive")
    private BigDecimal unitPrice;

    private BigDecimal totalPrice;    // Computed: unitPrice * quantity
}
```

Note: `@Getter`/`@Setter` instead of `@Data` — deliberate choice in `OrderItem` to avoid
implementing `equals`/`hashCode` based on price, which could cause issues in collections.

## OrderStatus Lifecycle

```java
public enum OrderStatus {
    DRAFT,              // Initial state — order created but not yet sent for payment
    PENDING_APPROVAL,   // Awaiting approval (manual or automated)
    APPROVED,           // Approved but not yet processed
    REJECTED,           // Rejected by approver
    SENT_TO_ERP,        // Sent to external ERP system
    COMPLETED,          // Payment confirmed — final success state
    CANCELLED           // Payment failed or cancelled — final failure state
}
```

Current flow (automated):
1. Client creates order → status is not explicitly set (null or DRAFT).
2. `vendas-topico` is published with orderId.
3. Payment service simulates payment.
4. `OrderPaymentListener` sets status to `COMPLETED` or `CANCELLED`.

## ApprovalStatus States

```java
public enum ApprovalStatus {
    NOT_REQUIRED,         // No approval needed
    PENDING,              // Awaiting approval decision
    APPROVED,             // Approved
    REJECTED,             // Rejected
    REVISION_REQUESTED    // Sent back for revision
}
```

Set by `OrderPaymentListener`:
- `PAYMENT_SUCCESS` → `APPROVED`
- other → `REJECTED`

## Metadata Auto-Population (OrderMetadataListener)

`org.cedro.orderservice.listeners.OrderCreatedEventListener` is a Spring `ApplicationListener`.
A MongoDB `AbstractMongoEventListener` (`OrderMetadataListener`) handles auto-populating `Metadata`.

Expected pattern (to implement if not present):

```java
@Component
public class OrderMetadataListener extends AbstractMongoEventListener<Order> {

    @Override
    public void onBeforeSave(BeforeSaveEvent<Order> event) {
        Order order = event.getSource();
        Metadata meta = order.getMetadata() != null ? order.getMetadata() : new Metadata();

        if (meta.getCreatedAt() == null) {
            // First save
            meta.setCreatedAt(LocalDateTime.now());
            meta.setCreatedBy(SecurityContextHelper.getCurrentUsername());
            meta.setVersion(1L);
        } else {
            // Update
            meta.setVersion(meta.getVersion() + 1L);
        }
        meta.setUpdatedAt(LocalDateTime.now());
        meta.setUpdatedBy(SecurityContextHelper.getCurrentUsername());

        if (meta.getDeleted() == null) {
            meta.setDeleted(false);
        }

        order.setMetadata(meta);
    }
}
```

## OrderServiceImpl — Core Logic

`org.cedro.orderservice.service.impl.OrderServiceImpl`

Key behaviors:
1. Extends `AbstractService<Order>` — gets CRUD for free.
2. Overrides `save()` to publish to Kafka after persisting.
3. `getRepository()` returns `OrderRepository`.
4. `getEntityClass()` returns `Order.class`.

```java
@Override
public ResponseEntity<Order> save(Order order, String returnEntity) {
    Order saved = orderRepository.save(order);
    String orderId = saved.getId();
    kafkaTemplate.send(VENDAS_TOPICO, orderId, orderId);
    log.info("Order {} saved and published to {}", orderId, VENDAS_TOPICO);
    return ResponseEntity.ok(saved);
}
```

## OrderPaymentListener — Status Update from Kafka

`org.cedro.orderservice.listeners.OrderPaymentListener`

Consumes `payment-processed` topic and updates order status:

```java
@KafkaListener(topics = "payment-processed", containerFactory = "orderPaymentListenerContainerFactory")
public void onPaymentProcessed(String payload) {
    try {
        JsonNode node = objectMapper.readTree(payload);
        String orderId = node.path("orderId").asText();
        String status = node.path("status").asText();

        orderRepository.findById(orderId).ifPresentOrElse(order -> {
            if ("PAYMENT_SUCCESS".equals(status)) {
                order.setStatus(OrderStatus.COMPLETED);
                order.setApprovalStatus(ApprovalStatus.APPROVED);
                order.setApprovedBy("payment-service");
                order.setApprovalDate(LocalDateTime.now());
            } else {
                order.setStatus(OrderStatus.CANCELLED);
                order.setApprovalStatus(ApprovalStatus.REJECTED);
            }
            orderRepository.save(order);
        }, () -> log.error("Order {} not found for payment update", orderId));

    } catch (Exception e) {
        log.error("Failed to process payment event. Payload: {}", payload, e);
    }
}
```

Note: uses `containerFactory = "orderPaymentListenerContainerFactory"` — a named factory bean
that must be declared in a `@Configuration` class.

## OrderCreatedEventListener

`org.cedro.orderservice.listeners.OrderCreatedEventListener`

A Spring `ApplicationListener<OrderCreatedEvent>` — fires on a Spring application event
(not a Kafka event). Currently only logs:

```java
@Override
public void onApplicationEvent(OrderCreatedEvent event) {
    log.info("Order created with ID: {}", event.getOrderId());
}
```

This is distinct from Kafka events. The `OrderCreatedEvent` is a Spring `ApplicationEvent`
published internally within the `order-service` JVM.

## Soft Delete for Orders

When deleting an order, set `metadata.deleted = true`:

```java
@Override
public void deleteById(String id) {
    orderRepository.findById(id).ifPresentOrElse(order -> {
        Metadata meta = order.getMetadata() != null ? order.getMetadata() : new Metadata();
        meta.setDeleted(true);
        meta.setDeletedAt(LocalDateTime.now());
        meta.setDeletedBy(SecurityContextHelper.getCurrentUsername());
        order.setMetadata(meta);
        orderRepository.save(order);
        log.info("Order {} soft-deleted", id);
    }, () -> { throw new ResourceNotFoundException(...); });
}
```

The `list()` and `count()` from `AbstractService` automatically exclude soft-deleted orders.
`findById()` does NOT exclude them — override if needed.

## Querying Orders by Status

Request: `GET /orderflow/v1/order?status=COMPLETED`

`AbstractService.buildQuery()` converts this to:
```java
Criteria.where("metadata.deleted").ne(true)
        .and("status").is("COMPLETED")
```

This works because `Order.status` is an enum, and MongoDB stores it as a string. The query
`is("COMPLETED")` matches the string representation.
